# 验证策略

测试按可观察行为与风险选择，不按改动文件、类、方法、层数或覆盖率机械配套。先查看相关已有测试，能证明本次改动就复用；只补真实缺口，不生成全仓覆盖矩阵或新审批。

## 选择主要验证入口

一条规则选择一个主要验证层，其他层只补独有风险，不重复完整输入矩阵。已有集成检查能证明简单规则时不强制另加单元测试；复杂算法的输入组合放轻量单元测试，集成检查关键接线与副作用。

| 改动 | 最小有效检查 | 需要额外验证的风险 |
| --- | --- | --- |
| 文档、注释、机械调整 | diff、引用、格式、必要编译 | 实际改变契约、配置或运行行为 |
| 简单 Controller 转发、普通 DTO | 复用已有接口/契约检查，不默认新测试 | 鉴权、校验、特殊序列化、金额单位或兼容性 |
| 业务计算、校验、状态规则 | 规则归属层的必要成功、拒绝和边界 | 调用层独有的映射、权限或副作用 |
| 行为不变的重构 | 现有相关测试 | 现有覆盖缺口或边界变化 |
| SQL、约束、事务、迁移 | 对应结构、迁移或数据库检查 | 目标数据库语义、数据兼容、回滚和并发 |

例如手续费边界在计算器充分验证，预览只检查结果和不冻结，提交检查正确落库或拒绝时不写入/不发送。不要求三个层各抄同一套金额场景。纯金额计算不因“资金”标签自动启动数据库；资金落库、重复付款和并发安全不能只靠 Mock。

简单转发、getter/setter、普通 DTO 自身 round-trip、无契约依据的全字段反射/源码文本断言不默认新增。实际路由、字段兼容、特殊序列化、安全边界和已知回归仍保留；反射或直接调用 Controller 不能证明真实 HTTP 鉴权链。

## TDD 与测试设施

RED 是可选开发手段，不是完成门槛，不要求跳过说明。可复现 Bug 优先用一个失败用例固定回归；复杂算法/状态机可先测后写，新功能可先实现后补必要验证。编译或环境失败不冒充行为 RED，不另写 RED/GREEN 阶段报告。

复用已有 fixture 和测试入口，不为测试方便增加生产 API、废弃重载、fallback 或测试专用补发/恢复平台。参数化用于减少重复，不默认穷举所有组合。只有确有重复才提取小型 fixture，不搭通用测试 DSL 或第二套契约包。

## 数据库的位置与频次

纯计算、转发、DTO 和未改变持久化行为的重构不默认启动数据库。简单可空列等变更先检查迁移、映射、兼容性，再按实际影响做目标数据库冒烟；静态检查不证明迁移实际成功。

复杂 SQL、数据库特有类型/JSON/索引、唯一约束、事务回滚、锁、并发和数据迁移，需要在适用数据库证明相应风险；H2 不能冒充 PostgreSQL 特有语义通过。复用已有本地隔离库、CI 临时库或经授权的隔离测试库，不默认新增基类、Profile、镜像或启动脚本。

同批相关改动集中验证；结果可能改变方案时提前验证，不把高风险未知一律拖到发布前。用户禁止本地数据库时不换引擎/容器绕过。缺环境时记录待办、负责人和完成条件，无关本地任务可继续，但相关验收或发布门槛未满足，不能声明通过。

启动环境、网络、资源及数据库写入遵守现有授权；不清空共享库/生产库，不使用真实敏感数据，不因测试自动扩权。

## 执行与复用

默认一批目标检查，有缺口或独有风险才扩大；遵守仓内必要最终回归，但集中执行，不因任务登记、切换 Agent、审查或内容等价提交重跑。同一内容、模块、依赖、profile/参数和构建输入的可信凭据可复用；漂移、缺口或可疑则重验。测试已编译的同一路径不额外 compile，不混淆不同构建入口。

不为减少测试行数删除有效回归；精简已有测试前确认剩余检查仍保护其行为。源码行为改变时重新说明范围。不以测试数量/行数或未经计费核实的 Token 降幅验收；实际检查、失败、目标跳过和未知结果仍如实登记。
