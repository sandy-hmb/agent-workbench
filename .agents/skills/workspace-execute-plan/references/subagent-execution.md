# 子 Agent 执行

仅在计划选择“按需子 Agent”或“每任务子 Agent＋独立审查”时使用。主 Agent 保留全局计划、授权和任务进度的责任；子 Agent 只处理一个边界明确的任务或审查。

## 交接

向实现者提供当前任务完整正文、直接依赖的结果、相关 R/D 验收、目标仓与工作目录、适用规范、允许修改的范围和验证命令。不要让它读取整个历史计划或会话；缺失信息由主 Agent补充。

实现者返回 `DONE`、`DONE_WITH_CONCERNS`、`NEEDS_CONTEXT` 或 `BLOCKED`，并列出实际修改、验证结果和遗留问题：

- `NEEDS_CONTEXT`：主 Agent 从当前文档或代码补充信息后继续同一任务。
- `BLOCKED`：先判断是否可通过补充上下文、缩小任务内部步骤或更强推理解决；只有计划本身无法安全裁定或需要新的用户权限时才升级给用户。
- `DONE_WITH_CONCERNS`：先处理影响正确性、范围或验收的问题，再进入审查。
- `DONE`：核对实际 diff 与测试后进入本模式要求的审查。

## 审查

“按需子 Agent”只在风险值得独立判断时审查。“每任务子 Agent＋独立审查”必须先检查需求符合性，再检查代码质量：

1. 需求符合性比较实际代码与当前任务、R/D 验收，找缺失行为和额外范围。
2. 代码质量检查正确性、错误处理、可维护性及适用规范。
3. 有重要问题时由实现者修复并定向复核；全部关闭后主 Agent才记录任务证据和完成状态。

一次只分派一个会修改相同工作目录的实现者。独立只读审查可以与无冲突工作并行，但并行不是这两种模式的默认行为。子 Agent 的完成声明、commit 或摘要不能代替主 Agent 的任务证据校验。
