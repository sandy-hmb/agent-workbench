# 子 Agent 执行

仅在计划选择“按需子 Agent”或“每任务子 Agent＋独立审查”时使用。主 Agent 保留全局计划、授权和任务进度的责任；子 Agent 只处理一个边界明确的任务或审查。多 Agent 宿主的 Agent 生命周期、Profile 与通知是运行事实，不替代 Kit 的任务和证据事实。

## 角色

- **主协调者**：拆分任务，确认授权和写入边界，选择实现者或只读审查者，检查实际结果并登记证据。
- **实现 worker**：只写入一个已准备好的任务的唯一目标仓；不修改 WorkItem 状态，不自行扩大任务或接管其他任务。
- **Advisor／Committee**：只读分析、方案或 diff 审查；不得创建、编辑或删除文件，也不得记录审批或完成。
- **Handoff 接手者**：仅在用户明确转交整项任务时接管协调责任。旧主停止后续派发；活动 worker 先完成或明确停稳，不能静默遗留并行写入者。

## 交接

向实现者提供当前任务完整正文、直接依赖的结果、相关 R/D 验收、目标仓与工作目录、适用规范、允许修改的范围和验证命令。交接还应包含 Kit 根、WorkItem slug、iteration、任务定义 revision，以及同一任务或 checkout 上已知的宿主 Agent。不要让它读取整个历史计划或会话；缺失信息由主 Agent 补充。

派发前核对当前 `brief --task`、实际分支、直接依赖和写入范围。`readyTasks` 只表示依赖和阻塞条件已满足，不表示尚未派发。主 Agent 排除仍在运行或待验收的同一任务、同一 checkout 写入者，主 Agent 自身也算写入者；直到回收、必要修复与证据记录完成才释放写入权。不同仓的独立任务可按授权并行，同仓默认串行。

宿主的 `ready`、`idle`、commit 或完成通知只提示回收，不是 Kit 完成事实。运行关联、模型和 Agent ID 由可选接入层管理，不进入 WorkItem 状态。创建结果不明时先核对已有 Agent，不能直接重派。宿主不可用时，确认没有运行中的写入者后再退回单 Agent；不得猜测性停止、reset、stash 或覆盖用户改动。

实现者返回 `DONE`、`DONE_WITH_CONCERNS`、`NEEDS_CONTEXT` 或 `BLOCKED`，并列出实际修改、验证结果和遗留问题。返回中必须说明：

- 修改路径及目标仓；
- 每个检查的工作目录、命令、退出码、实际执行数和跳过数；
- 当前 diff 是否包含无法归属或未处理的修改；
- 未验证行为、外部依赖和下一步。

- `NEEDS_CONTEXT`：主 Agent 从当前文档或代码补充信息后继续同一任务。
- `BLOCKED`：先判断是否可通过补充上下文、缩小任务内部步骤或更强推理解决；只有计划本身无法安全裁定或需要新的用户权限时才升级给用户。
- `DONE_WITH_CONCERNS`：先处理影响正确性、范围或验收的问题，再进入审查。
- `DONE`：核对实际 diff 与测试后进入本模式要求的审查。

## 审查

“按需子 Agent”只在风险值得独立判断时审查。“每任务子 Agent＋独立审查”必须先检查需求符合性，再检查代码质量：

1. 需求符合性比较实际代码与当前任务、R/D 验收，找缺失行为和额外范围。
2. 代码质量检查正确性、错误处理、可维护性及适用规范。
3. 有重要问题时由实现者修复并定向复核；全部关闭后主 Agent才记录任务证据和完成状态。

一次只分派一个会修改相同实际 checkout 的实现者。独立只读审查可以与无冲突工作并行，但并行不是这两种模式的默认行为。子 Agent 的完成声明、commit 或摘要不能代替主 Agent 的任务证据校验。整体验证开始后暂停相关仓的新写入，直到主 Agent 已核对结果。
